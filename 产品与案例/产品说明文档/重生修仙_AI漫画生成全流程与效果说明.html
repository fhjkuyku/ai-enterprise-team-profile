AI漫画生成全流程与效果说明

以《重生修仙：我为大圣寻心魂》为完整样例，说明一话漫画如何从锁定剧情，经过脚本、文字、分镜、视觉资产、提示词与生图验收，最终成为可发布的16张竖版成图。

01 / PRODUCT OVERVIEW

从“写提示词出图”，
升级为可审计生产线

这套流程把最容易漂移的内容拆成独立权威层：剧情只认正史，最终可见文字只认文字锁，页面结构只认故事板，生图只消费通过预检的逐图提示词。任何问题都回到最早责任阶段处理。

1唯一剧情事实源
10G0–G9 阶段门
3×5三个五页叙事段
15正文竖版页面
16封面 + 正文位图
核心价值：前期把剧情、文字、二维页面拓扑和视觉版本锁清楚，生图阶段只执行，不再临时补剧情、改台词或重做分镜；既降低内容漂移，也让局部返工不必推倒整话。
02 / SYSTEM ARCHITECTURE

三层权威，各管一件事

“谁有权改什么”比工具数量更重要。流程通过权威文件与哈希，把创作判断、生产执行和发布状态彼此隔离。

01

正史层

人物、世界、事件、知识边界与状态变化只保存在 Story Skills。漫画资料是派生产物，不能反过来发明事实。

story/ → final canon
02

生产层

脚本、文字锁、分镜、视觉就绪和提示词包逐级编译。每个阶段只处理自己的职责，并保留来源和依赖哈希。

G0 → G7
03

发布层

生图后逐页记录状态，整话再做发布门。技术失败与非技术偏差分流，避免系统擅自重生或偷偷修图。

G8 → G9
03 / END-TO-END FLOW

从定稿故事到发布成图

每一格都有上游依据，每一条字都有唯一 ID，每一张图都有生成报告。下游发现问题时，不“顺手改”，而是按责任回流。

G0 准入

确认来源已定稿、单话职责与知识边界成立。

G1 完整漫画脚本

同时完成外部行动、内部体验与全部文字初稿。

G2 正史回写

只有新增或改变事实时执行；否则记为无需。

G3 来源冻结

锁定最终事件、状态、范围、路径与哈希。

G4 文字锁

锁定全部可见文字，不提前分配最终页码。

G5 二维分镜

分配P01–P15、真实画格、阅读路径与文字挂载。

G6 视觉就绪

核对文字视觉、角色、服装、地点、道具与参考版本。

G7 提示词编译

生成16份最终提示词与可验证提示词包。

G8 生成与筛查

逐图生成，记录可用、待复核、阻塞或技术失败。

G9 发布门

确认16图齐全、无阻塞，组装PDF并登记索引。

04 / STAGE GUIDE

每个阶段做什么，
怎样才算通过

下面按真实交接关系说明输入、动作与结果。这里的“通过”，指文件已经能够被下一阶段安全消费。

G0
输入

已达 final 的章节/场景、全局刺激登记、项目配置与连续性状态。

处理

确认本话来源、剧情职责、知识边界、生产模式；不写具体剧情，不分配页码。

通过产物

episode-brief.md：事实范围、刺激适配与准入结论明确。

G1
输入

G0简报与正史来源。

处理

写完整可连续阅读的漫画脚本：目标、冲突、选择、结果、外部行动、内部体验、文字初稿、叙事桥和话尾钩子。

通过产物

episode-script.md + content-inventory.yaml；没有“此处独白”“待定”等占位。

G2–3
输入

用户确认后的G1脚本与正史差异。

处理

有事实变化才回写正史；随后冻结最终来源、状态、依赖与哈希。无变化时G2直接记为 not-required。

通过产物

source-lock.md 可复现且不成为第二份正史。

G4
输入

G1全部文字初稿 + G3来源锁。

处理

编辑口吻、句长、力度与准确性；为对白、独白、旁白、系统与功能文字分配唯一 text_id。

通过产物

text-lock.md / cover-lock.md；准确文字、来源、知情边界与画文关系全锁定。

G5
输入

完整脚本、内容清单、来源锁、文字锁、项目页序列。

处理

把节拍分配到P01–P15，设计非对称二维页面、真实画格、视觉区、阅读路径、转场与text_id挂载。

通过产物

storyboard.md + storyboard-audit.json；内容覆盖、拓扑与叙事桥全部通过。

G6
输入

G5页面蓝图、视觉指南与共享视觉版本。

处理

确定文字框、字形、层级、负空间、移动端可读性；确认角色/服装/地点/道具和参考图版本。

通过产物

visual-readiness.md；所有生图依赖均存在且版本有效。

G7
输入

G5故事板 + G4准确文字 + G6视觉资产 + 项目视觉规则。

处理

逐图编译自然语言提示词，计算依赖SHA-256，隔离生产ID，运行共享验证器与项目整链预检。

通过产物

compiled/ 16份提示词 + prompt-package.json；0错误后才允许生图。

G8
输入

通过预检的16份提示词与参考资产。

处理

按封面、P01–P15顺序生成；逐页筛查剧情节点、人物、关键文字、顺序、视觉效果和分镜落地。

通过产物

images/ + generation-report.json；非技术偏差只记录，不擅自重做。

G9
输入

16张成图、G8逐图状态与跨话连续性资料。

处理

确认无未解决阻塞；按输出顺序组装漫画PDF，验证页数与抽样渲染，更新单话清单和全书索引。

通过产物

production-manifest.json + 漫画索引 + 16页PDF（项目要求时）。

检查点 1｜G1 后
确认实际剧情、人物目标/冲突/变化、内部体验、文字方向和话尾钩子。
检查点 2｜G4 后
确认全部准确文字、人物声音、文字节奏及画面与文字的关系。
05 / HOW TO USE

日常使用：只需说明话数与目标

系统会先读取项目配置和生产索引，再从最早未通过门槛继续。你不需要手动告诉它每个文件该放哪里，但需要明确是“新制、恢复、审查”还是“指定返工”。

准备定稿来源

确保目标话对应章节和场景达到 final；若未定稿，先完成小说侧策划与确认。

提出生产目标

告诉系统话数、是否全流程、是否允许自动继续到G8/G9，以及你最关心的效果。

在语义检查点确认

默认在G1与G4确认；若希望自动继续，应明确授权，但正史变更仍需先确认。

查看生成报告

重点看 usable、user-review、production-blocker、technical-failure 四类状态及逐页备注。

按责任阶段返工

只改受影响页面和必要转场；不让一个局部问题无条件拖垮整话。

新制作一话
按本项目漫画生产流程制作第002话。先检查正史是否满足G0；若满足，从G0开始推进到G7预检。G1和G4给我确认，未确认前不要生图。
恢复未完成生产
检查第002话的 production-manifest 和权威文件，从最早未通过的门槛继续。复用哈希一致的上游产物，报告哪些复用、哪些失效、下一允许阶段是什么。
授权连续完成
第002话G1剧情与G4文字确认后，允许继续完成G5–G9。必须先通过两套G7预检；成图非技术偏差只记录为 user-review，不自动重生。
指定页面返工
处理第001话P13的视觉备注。先判断问题属于G5、G6、G7还是G8；只失效受影响页面及必要转场，不改未受影响的剧情、文字和页面。
06 / FILE HANDOFF

每一份文件，都是明确交接物

正式目录只放权威产物；调试候选与临时分析进入 _work。这样恢复生产时只需读取索引与清单，不会把旧稿、废稿或试验图误当成当前版本。

08 / QUALITY CONTROL

验收聚焦六项
生产可落地指标

生图前解决结构与依赖问题，生图后只判断实际图是否能承担生产任务。装饰数量和轻微风格偏差不自动触发重生。

验收维度必须回答的问题不通过时
剧情节点关键行动、结果、因果和话尾钩子是否完整落地？回G1 / G5
人物身份、造型、动作归属与active视觉版本是否一致？回G6 / G8
关键文字准确文字是否可读、无姓名前缀、无生产编号、无语义漂移？回G4 / G7
页面顺序封面与P01–P15是否齐全、唯一、顺序正确？回G7 / G9
视觉效果画风、光效、氛围、文字层级与移动端可读性是否成立？回G6 / G8
分镜设计二维拓扑、阅读路径、信息层级和页尾推进是否真正落地？回G5
预检铁律：G7只有在16份提示词齐全、所有依赖哈希一致、生产ID隔离、文字零漂移、两套验证器通过后，才会把 image_generation_allowed 设为 true。
09 / REWORK ROUTING

问题出现在哪里，就回到哪里

返工采用“最小失效范围”。例如只改一页提示词，不应使未受影响的G1剧情和G4文字失效；但如果新增剧情事实，则必须回到上游刷新来源锁。

G1

剧情、冲突、选择、情绪、钩子，或需要新增文字叙事点。

G2–3

事实、因果、知识、伏笔、规则或人物状态发生改变。

G4

现有文字的口吻、句长、准确性、力度或拆分方式。

G5

页码、画格、镜头、二维拓扑、阅读路径或文字挂载。

G6

字形、框形、负空间、角色/服装/地点/道具版本。

G7

提示词、参考图映射、哈希、生产ID污染或元数据。

G8

单页技术失败或成图的非技术视觉偏差。

G9

文件不齐、连续性断裂、PDF验证失败或无法发布。

10 / BOUNDARIES

适用边界与常见误区

流程追求“内容丰富、视觉华丽、生产可控”，但不通过凑格数、堆特效或虚构细节制造表面完成度。

这套流程擅长

  • 基于已确认正史的连载剧情漫画。
  • 人物主观判断和情绪压迫较强的独白叙事。
  • 手机纵向阅读下的二维非对称页面。
  • 需要跨话角色、服装、道具和封面身份连续的项目。
  • 需要可恢复、可局部返工、可追踪依赖的团队生产。

这套流程不会做

  • 不会用固定画格数、文字比例或无字页配额反推内容。
  • 不会把 vertical-scroll 简化成连续单列横条。
  • 不会在分镜或提示词阶段补写没有正史来源的剧情。
  • 不会把生产ID、页码、格号或制作备注交给图像模型。
  • 不会因非技术偏差自动裁切、叠字、修补或重生。
